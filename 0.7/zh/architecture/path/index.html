    路径

    一行在服务中的路径：领取、投递、解码、处理器、应答和结算。行可以逐行处理、按批处理，或者以行本身交给处理器。

    领取按表的领取方式把行取来处理，每一行变成一个 InboxDelivery：其中有驱动程序解码出的行、它的 id、它的尝试次数，以及领取方式为它持有的东西，即一个事务、一个租约令牌或一个键的连接。在载荷模式下，编解码器直接从行的列中读取载荷：字节是借用的，不做复制。消息头在第一次读取时才构建，因此从不读取消息头的处理器不为它们付出开销。载荷无法解码的行由订阅的解码策略结算。

    在行模式下，表没有载荷列，处理器接收驱动程序读出的行本身，即 &Row。不运行编解码器，也不复制任何东西。

    一个批就是一次领取：最多批大小那么多行，一起投递，每行单独解码。无法解码的行由解码策略结算，批中的其他行保留。批中的每个投递结算自己的行。在行锁方式下，一个批的各行共用领取的事务，因此它们的结算在最后一个完成时一起生效，一条语句失败就会回滚整个批。在租约方式和咨询锁方式下，每行各自结算。

    应答被编码进分发循环复用的缓冲区，本 crate 的发布者以借用切片的形式接收它。默认的应答发布者 Routed 在 Broker 的路由中查找应答的名称，并通过行的 Publish 实现插入它。插入之前，它检查 Broker 尚未关闭，并且表能容纳消息的每个消息头。插入之后，在 listen_notify 下它用 pg_notify 通告这一行，并唤醒本进程中订阅了该表的订阅。投递在应答之后结算，结算一页用图说明了这一点。

    基准测试公布每条路径上一条消息的开销，以指令数和内存分配次数计，并与执行相同语句的裸 sqlx 循环对照。
