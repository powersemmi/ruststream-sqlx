# SQL 数据库 { #sql-databases }

`ruststream-sqlx` 通过 [`sqlx`](https://docs.rs/sqlx) 把 SQL 数据库接入
[RustStream](https://powersemmi.github.io/ruststream/) 服务。它包含两个组件：

- 事务性发件箱（transactional outbox），可配合任意 RustStream Broker 使用。
  发布消息时，消息会作为一条记录写入服务自己的表，并携带这条记录的 ID。
  订阅根据该 ID 领取任务并开始处理，确认后将任务标记为已处理。
  服务启动时，会重新发布所有尚未处理的记录。
- 任务队列，存放在服务自己的 Postgres、MySQL/MariaDB 和 SQLite 表中。

订阅以三种方式之一领取队列中的行。在行锁方式下，订阅在事务中锁住这一行，
事务一直保持打开，直到处理器处理完这一行。在租约方式下，订阅把租约写入这一行，并立即提交事务。
因此，耗时较长的处理器不会占用事务，订阅还会在处理器运行期间为租约续期。
在咨询锁（advisory lock）方式下，订阅在为这次投递服务的那条连接的数据库会话中，锁住这一行的键。
这时不会有事务一直保持打开，键相同的行会逐一进入处理。SQLite 表使用租约方式或咨询锁方式。

处理器收到的是行中的消息，由编解码器从表的载荷列解码得到。没有载荷列的表采用行模式：
处理器直接收到这一行本身，也就是 sqlx 读出的服务自己的结构体，中间不经过编解码器。
批处理器以一个切片收到一次领取的全部行。

队列表也可以由一个专门的头部结构体描述：其中包含驱动队列的各列，以及服务自己的消息头。
这时，处理器收到的是消息结构体。它包含头部结构体和消息自己的数据，
服务可以用自己的查询通过 `JOIN` 从其他表读取这些数据。
投递的消息头由头部结构体的字段构成，只在有人读取时才构建。

订阅发现队列为空后，会等待一个轮询间隔。通过 Broker 发布的消息，会立即唤醒同一进程中该表的订阅。
在 Postgres 上，`listen_notify()` 还会在收到其他进程的通知时唤醒订阅。
为此，Broker 会占用连接池中的一个连接，每次发布还会多执行一条语句。
由于 Postgres 在提交发送通知的事务时，会获取一把整个服务器共用的锁，这类事务只能逐个提交，
因此大量并发写入会受到限制。

用 `.transactional()` 注册的处理器，在三种方式下都可以通过本次投递的事务写入数据。
确认会在同一个事务中提交处理器的写入，并完成这一行。其他任何结果都会回滚这些写入。
投递处理期间，它的事务会占用连接池中的一个连接。

订阅通过 `max_attempts(n)` 限制一条消息的投递次数，并通过 `dead_letter(..)` 指定一个分组或一张表。
一行的尝试次数耗尽后，会转入该分组或该表。两者需要一起声明。使用 `max_attempts(1)` 时，每次失败都会让该行立即转入。

驱动队列的各列各自承担一个角色，每个角色开启一种行为：订阅读取的分组、行进入处理的顺序、保持相关行顺序的键、
重新处理前的延迟、尝试次数，以及让已处理的行保留在表中、不再删除的标记。
表默认从主机的时钟读取当前时间，也可以改为读取数据库的时钟，这样所有主机读到的都是同一个时间。

服务可以在自己的结构体上用 `#[derive]` 描述队列表，也可以手写描述。手写时，结构体实现一个 trait，
表的全部设置由一个带类型的构建器给出。编译器检查这份描述，与检查 `#[derive]` 一样严格。
两种方式生成相同的语句，每条消息的开销也相同。

这个 crate 内置了 Postgres、MySQL/MariaDB 和 SQLite 的方言。服务要用自己的方式编写某条语句时，
把它作为事件：表在 `#[derive]` 的 `custom(..)` 中或在手写描述的构建器中指明该事件，
结构体实现对应的 trait。没有内置方言的数据库，
由服务编写自己的方言。这样的方言为其表采用的每种方式实现一个 trait，
并为按名称订阅实现一个 trait。表采用的方式在方言中不存在时，代码无法编译。

队列表归服务所有。启动时，订阅会检查它的表中有没有结构体列出的各列。
列的类型由服务自己负责。某一行无法解码为结构体时，订阅按自己的解码失败策略处置这一行。

在编译期检查 SQL 的团队，可以在 `#[derive]` 中加上 `checked` 和数据库名。
这样 `#[derive]` 会把它生成的语句交给 sqlx 的编译期宏，`cargo sqlx prepare` 会连同服务自己的查询一起，
按数据库检查这些语句。启动时的检查照常进行。

## 其余内容在哪里 { #where-the-rest-is }

这个 crate 的参考文档在 docs.rs 上：[`ruststream-sqlx`](https://docs.rs/ruststream-sqlx)。

这个 crate 每条消息的开销，以及它每秒处理的消息数，与做同样工作的原生 sqlx 循环的对比，见[基准测试页面](benchmarks.md)。

处理器、路由器、编解码器和中间件都来自框架本身，它的入口页面从
[RustStream 站点](https://powersemmi.github.io/ruststream/)开始。
