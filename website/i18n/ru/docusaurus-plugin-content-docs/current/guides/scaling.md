# Несколько экземпляров и пробуждение воркеров

Это руководство запускает очередь на нескольких экземплярах сервиса с несколькими воркерами в каждом и задаёт, как быстро они видят новую задачу.

Таблица очереди общая для всех экземпляров, которые её читают.
Экземпляры координирует только база данных: каждый захватывает строки, а [форма](../components/forms/index.md) таблицы держит любую строку не больше чем в одном захвате одновременно.
Два захвата никогда не берут одну и ту же строку, в любой форме и на любой базе данных.

Пример строит счета-фактуры.
Магазин записывает задачи на счета собственным SQL, а сервис построения работает на стольких экземплярах, сколько требует нагрузка.

[`workers(4)`](../components/subscriptions/workers.md) строит в каждом экземпляре до четырёх счетов одновременно.
Подписка держит по захвату на каждого свободного воркера, поэтому её воркеры берут строки сразу, а не друг за другом.
На SQLite, который допускает одного писателя за раз, она держит один захват, и в форме аренды этот захват берёт по строке на каждый воркер.
Второй экземпляр на той же таблице добавляет ещё четыре воркера, и ни один счёт не попадает к обоим.

## Как быстро видна новая задача {/* #how-fast-a-new-job-is-seen */}

Подписка захватывает, пока её захваты возвращаются полными, поэтому накопившиеся строки разбираются без пауз.
После захвата, который нашёл меньше строк, чем просил, она ждёт [интервал опроса](../components/subscriptions/poll-interval.md), по умолчанию одну секунду.
Сколько ждёт новая строка, определяют три вещи:

- Публикация через брокер сразу [будит](../components/wake/index.md) подписки своей таблицы в том же процессе, ценой одной атомарной операции на каждую разбуженную подписку.
- Строка, записанная иначе, ждёт интервал опроса: вставка другой программы, триггер, [`insert`](../components/tables/insert.md) сервиса, публикация из другого экземпляра.
  Здесь `poll_interval(250 ms)` ограничивает это ожидание четвертью секунды ценой четырёх операторов захвата в секунду на каждую подписку на пустой таблице.
- На Postgres ожидание заканчивает уведомление.

[`listen_notify()`](../components/wake/listen-notify.md) слушает на одном соединении пула, а каждая подписка слушает канал своей таблицы.
Каждая публикация брокера выполняет `pg_notify(channel, group)` сразу после своей записи, поэтому подписка в другом экземпляре захватывает строку, как только та становится видна.
Писатель вне RustStream отправляет такое же уведомление сам; триггер выше делает это при каждой вставке, а его пустая полезная нагрузка будит каждую подписку таблицы.
С уведомлениями интервал опроса становится запасным путём для того, что уведомление пропустило, здесь минута.

У уведомлений есть цена, и если переключатель не задан, они выключены.
Брокер держит одно соединение пула на всё время своей жизни.
Каждая публикация выполняет ещё один оператор.
Транзакция, которая отправляет уведомление, при фиксации берёт блокировку, глобальную для сервера, поэтому фиксации таких транзакций выполняются одна за другой; сервис с множеством одновременных писателей измеряет это, прежде чем включать уведомления ([NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html)).

## Воркеры и пул {/* #workers-and-the-pool */}

Подписка никогда не держит больше соединений, чем размер пула минус одно, поэтому в пуле всегда остаётся одно для обработчиков, их публикаций и завершений.
Пул, слишком маленький для своих воркеров, выполняет меньше доставок одновременно, но не возвращает ошибку.
В форме аренды пул из `n + 1` соединений позволяет каждому свободному воркеру `workers(n)` захватывать одновременно; формы блокировки строк и рекомендательной блокировки к тому же держат соединение на каждую задачу в работе ([Соединения](../components/broker/connections.md)).
Пул для всего сервиса рассчитывает руководство [Работа в промышленной среде](production.md).

## Часы {/* #clocks */}

Каждый экземпляр читает «сейчас» по часам своего хоста, чтобы захватывать, откладывать и арендовать строки ([Время](../components/time/index.md)).
Хосты, которые обслуживают одну таблицу, держат часы согласованными, с расхождением намного меньше срока аренды, как это делает NTP.
Где это невозможно, таблица на [`DatabaseClock`](../components/time/database-clock.md) читает часы базы данных в каждом операторе; форма аренды сохраняет часы хоста, поэтому такая таблица использует форму блокировки строк или рекомендательной блокировки.

## Тестирование {/* #testing */}

Тесты в файле примера запускают сервис на SQLite в памяти.
Два экземпляра, каждый со своим пулом, стартуют на одной таблице с двадцатью счетами и вместе строят каждый счёт один раз.
Строку, которую записала другая программа, сервис видит в пределах четверти секунды интервала опроса.
Публикация через брокер сразу доходит до своего экземпляра.
Эти строки не будят ни одну подписку, поэтому тесты, которые их ждут, работают на реальных часах через [`TestApp::start_live`](../components/testing/live.md).
Последний тест запускает сервис для Postgres на собственной базе данных и находит, что вставка захвачена задолго до опроса раз в минуту; он читает адрес сервера из `POSTGRES_TEST_URL` и без него пропускается.
