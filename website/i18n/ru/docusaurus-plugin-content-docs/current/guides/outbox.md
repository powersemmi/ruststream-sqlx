# Отслеживание публикаций: плагин outbox

Это руководство доводит каждое сообщение, которое публикует сервис, до обработчика, который его обработает, на брокере, который ничего не хранит.

Некоторые брокеры доставляют сообщение только тем, кто слушает в этот момент, среди них Redis Pub/Sub и NATS core, а получатель может остановиться на середине любого сообщения.
[Outbox](../components/outbox/index.md) записывает каждое сообщение, которое сервис публикует под зарегистрированным именем, отмечает запись, когда получатель обработал сообщение, и при старте снова публикует необработанные записи.
Это плагин поверх любого брокера RustStream, и ему не нужен процесс-ретранслятор.
Его фича `outbox` не зависит от inbox.

Пример принимает оплату при оформлении заказа и отгружает оплаченные заказы, на брокере в памяти.

[`outbox!`](../components/outbox/registry.md) регистрирует `payments` с его записью; имя, зарегистрированное дважды, не компилируется.
`#[ruststream::app]` строит приложение до того, как появится рантайм Tokio, а sqlx строит пул только внутри него.
Поэтому реестр стартует без пула, а [`on_startup`](../components/outbox/set-pool.md) строит пул и передаёт его через `set_pool`; `after_shutdown` закрывает его.

Отслеживаемое сообщение проходит четыре шага:

1. [Слой публикации](../components/outbox/tracking.md) сохраняет запись, а затем отправляет сообщение с id записи в заголовке `x-ruststream-outbox-id`. Если запись не удалось сохранить, публикация возвращает ошибку.
2. Слой подписки по id берёт доставку, у которой есть id, в работу и запускает обработчик; копия, запись которой уже обработана, подтверждается без обработчика.
3. Подтверждение или `drop` обработчика отмечают запись обработанной; переобработка оставляет её как была.
4. При старте [`republish`](../components/outbox/republish.md) снова отправляет каждую необработанную запись, когда подписки уже открыты.

Получатель отмечает запись в таблице издателя, поэтому издатель и получатель разделяют реестр и базу данных, как здесь оба обработчика одного приложения.

## Что гарантирует outbox {/* #what-the-outbox-guarantees */}

Сообщение доставляется хотя бы один раз.
Запись сохраняется до отправки сообщения, поэтому неудачная отправка, получатель, который остановился посреди обработчика, или обработчик, который просит сообщение снова, оставляют запись до следующего старта.
Два экземпляра, которые стартуют одновременно, могут оба снова отправить одну и ту же запись, поэтому получатель, который не должен обрабатывать сообщение дважды, проверяет это сам.

Запись сохраняется на собственном соединении и фиксируется сразу.
Она не входит в транзакцию сервиса: [транзакционный](transactional.md) обработчик inbox, который уходит на переобработку, отбрасывает свои записи в базу данных и сохраняет запись о том, что опубликовал.
На SQLite такой обработчик публикует до своей первой записи через свою транзакцию, потому что иначе вставка записи outbox ждёт блокировку записи этой транзакции ([Взаимодействие](../components/outbox/interplay.md)).
Событие, которое должно фиксироваться вместе с бизнес-строками, - это строка бизнес-транзакции, которую затем ретранслируют: [Ретрансляция событий в другой брокер](relay.md).

Публикация вне обработчика, например из конечной точки HTTP, берёт издателя работающего приложения и [оборачивает](../components/outbox/wrap.md) его в реестр через `wrap`, поэтому она отслеживается так же.
Отслеживание стоит одно соединение на каждую отслеживаемую публикацию и два на каждую отслеживаемую доставку: одно на получение записи, одно на завершение.
Сообщение под именем, которого нет в реестре, стоит одно сравнение имён.
[`examples/outbox`](https://github.com/powersemmi/ruststream-sqlx/tree/main/examples/outbox) в репозитории выполняет тот же сценарий поверх Redis Pub/Sub, с миграциями и собственным получением записи.

## Тестирование {/* #testing */}

Тестовая сборка оставляет outbox выключенным, если его не включает `RUSTSTREAM_SQLX_OUTBOX=on` ([Переключатель](../components/outbox/switch.md)), поэтому собственные тесты сервиса запускают его обработчики без отслеживания.
Тесты в файле примера, которые проверяют отслеживание, без переключателя пропускаются; ещё один тест проверяет, что при выключенном переключателе сервис работает без отслеживания:

```bash
cargo test
RUSTSTREAM_SQLX_OUTBOX=on cargo test
```

При включённом переключателе один тест проверяет, что оплата записана, отправлена с id своей записи и отмечена после отгрузки.
Другой записывает запись, которую предыдущий экземпляр оставил необработанной, и находит её отгруженной после старта.
Оба работают через [`TestApp::start`](../components/testing/index.md) на базе данных SQLite в памяти, которую открывает по URL собственный пул сервиса.
