# Долгие задачи, сбои и форма захвата

Это руководство выбирает, как таблица очереди держит задачу, пока над ней работает обработчик, и показывает, что происходит с задачей, которая выполняется минуты или процесс которой аварийно завершился.

Захваченная задача не должна попадать в другие захваты, пока не завершится, и должна вернуться, если её процесс остановился.
Для этого описание таблицы выбирает одну из трёх [форм](../components/forms/index.md), а обработчик во всех них один и тот же.

## Три формы {/* #the-three-forms */}

| | Блокировка строк | Аренда | Рекомендательная блокировка |
|---|---|---|---|
| Как выбирается | ничем: форма по умолчанию | `#[field(locked_until)]` | `#[inbox(advisory_lock = "..")]` |
| Чем держит задачу | транзакцией захвата, `FOR UPDATE SKIP LOCKED` | сроком, записанным в строку | блокировкой ключа строки, которую держит сеанс |
| Соединения | одно на задачу в работе, на всё время обработчика | одно на оператор | одно на задачу в работе |
| После сбоя | задача возвращается сразу | задача возвращается, когда истекает её аренда | задача возвращается сразу |
| Сбой тратит попытку | нет | да | да |
| Базы данных | Postgres, MySQL, MariaDB | все | все |

[Блокировка строк](../components/forms/index.md) держит транзакцию захвата открытой, пока работает обработчик, а завершение её фиксирует.
Транзакция аварийно завершившегося процесса откатывается, поэтому его задачи сразу возвращаются, а их попытки не засчитываются.
Цена - соединение на каждую задачу в работе.
В SQLite нет блокировок строк, поэтому таблица на SQLite указывает одну из двух других форм.

[Аренда](../components/forms/lease.md) фиксирует захват сразу, поэтому задача в работе не держит ни соединения, ни транзакции.
Она подходит для долгих задач, и это форма очереди на SQLite.
[Рекомендательная блокировка](../components/forms/advisory.md) держит каждую задачу по ключу: ключ по id держит каждую задачу отдельно, а ключ по другому столбцу пускает задачи с одинаковым ключом в работу по одной.

Захват записывает срок аренды в `locked_until` и засчитывает попытку.
Пока работает `render`, подписка продлевает аренду раз в половину её срока, поэтому отчёт может строиться пять минут при аренде в одну минуту.
Срок служит токеном владения доставкой: подтверждение удаляет строку, только пока строка всё ещё держит эту аренду.
[`InboxQueue::lease`](api:ruststream_sqlx::InboxQueue::lease) задаёт аренду одной подписки, а [`SqlxBroker::lease`](api:ruststream_sqlx::SqlxBroker::lease) - аренду брокера; если её не задать, она равна тридцати секундам, в целых секундах.

## Что делает сбой {/* #what-a-crash-does */}

Процесс, который аварийно завершился посреди отчёта, перестаёт продлевать аренду.
Строка остаётся вне очереди, пока аренда не истечёт, здесь минуту, а затем её берёт следующий захват.
Этот захват засчитывает ещё одну попытку, поэтому `render` видит вторую попытку и пишет её в журнал.
Значит, аренда - это время, на которое сбой задерживает задачу: короткая аренда возвращает её раньше ценой большего числа продлений.
Живой процесс, который перестал продлевать аренду, потому что дольше её срока не мог связаться с базой данных, теряет задачу: её берёт другой захват, а его запоздалое завершение возвращает ошибку [`SqlxBrokerError::LeaseLost`](api:ruststream_sqlx::SqlxBrokerError::LeaseLost).

Блокировка строк и рекомендательная блокировка заканчиваются вместе со своим сеансом, поэтому сбой сразу возвращает задачи.
При завершении работы брокер перестаёт продлевать аренды: задача в работе сохраняет свою аренду и завершается, если успевает, а иначе возвращается, когда аренда истекает.
Рекомендательные блокировки снимаются при завершении работы ([Завершение работы](../components/broker/shutdown.md)).

## Пул для каждой формы {/* #the-pool-each-form-needs */}

Блокировка строк и рекомендательная блокировка держат соединение на каждую задачу в работе, поэтому подписке с `workers(8)` только для её задач нужно восемь соединений.
Аренда держит соединение только на время каждого оператора.
Каждая подписка оставляет в пуле одно соединение для обработчиков, их публикаций и завершений ([Соединения](../components/broker/connections.md)).
На Postgres рекомендательной блокировке нужно прямое соединение или PgBouncer в режиме сеанса, потому что блокировка принадлежит сеансу.
На SQLite ключи задач в работе хранит процесс, поэтому один файл базы данных обслуживает один процесс.
Размер пула выбирает руководство [Работа в промышленной среде](production.md).

## Тестирование {/* #testing */}

Тесты в файле примера запускают сервис на SQLite в памяти.
Первый останавливает часы, поэтому пять минут построения отчёта проходят мгновенно, а продления аренды выполняются, когда часы доходят до них; отчёт доставляется один раз.
Второй записывает две строки, которые захватил другой процесс: одну с истёкшей арендой и одну с действующей.
Возвращается только первая.
Эти строки не будят ни одну подписку, поэтому тест работает на реальных часах через [`TestApp::start_live`](../components/testing/live.md) и ждёт дольше интервала опроса.
