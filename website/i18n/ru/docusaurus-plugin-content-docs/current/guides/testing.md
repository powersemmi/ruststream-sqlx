# Тестирование сервиса на SQL

Тест запускает собственное приложение сервиса через [`TestApp`](api:ruststream::testing::TestApp) на настоящей базе данных: на SQLite в памяти или на собственной базе данных теста на сервере.

Поведение очереди задаёт её SQL: захват, завершение, собственный `Publish` сервиса.
Поэтому у обвязки нет модели базы данных.
Её [режим в процессе](../components/testing/index.md) выполняет операторы сервиса на той базе данных, к которой обращается пул теста, и ведёт учёт, по которому ждёт обвязка.

Тестируемый сервис делает миниатюры.
Миниатюра маленького изображения делается сразу.
Большое изображение программа масштабирования принимает только со второй попытки, поэтому первая доставка большого изображения откладывается на минуту через [`retry_after`](../components/settlement/retry-after.md).
Приложение строит `service(pool)`, поэтому тест выбирает базу данных, а `main` берёт рабочую.
Тестам нужна фича `testing` крейта `ruststream-sqlx` в `[dev-dependencies]`.

`database` создаёт базу данных SQLite в памяти, общую для всех соединений, которые её называют.
Она существует, пока открыто хотя бы одно из этих соединений, поэтому тест держит одно рядом с пулом и создаёт таблицу так, как это сделали бы миграции сервиса.
[`TestApp::start`](api:ruststream::testing::TestApp::start) подключает к ней рабочее приложение в процессе, а тест обращается к брокеру по его рабочему типу, `tb.broker::<SqlxBroker<Sqlite>>()`.

Изображение попадает в очередь через маршрут и собственный `Publish` сервиса, как в промышленной среде.
`publish` возвращает управление, когда разбуженный им обработчик завершил строку, поэтому строки теста после него читают уже готовое состояние: как `thumbnail` завершил строку и что находит в таблице собственный запрос теста.
Строка, которую тест пишет собственным SQL, засчитывается, только когда её берёт захват, поэтому `settle` её не ждёт; такой тест работает на реальных часах и пропускает интервал опроса, как в руководстве [Постановка задач в очередь](enqueueing.md).
Сценарий принимает дескриптор брокера аргументом, поэтому его выполняет и тест на Postgres ниже.

Таблица без столбца полезной нагрузки передаёт обработчику саму строку ([Строки](../components/messages/rows.md)).
Тест такого обработчика проверяет строку через `with_value` и `received_values` вместо `with` и `received`.

В процессе очередь читает «сейчас» по часам tokio, привязанным к системным часам в момент подключения брокера.
Тест останавливает эти часы, а [`advance`](api:ruststream::testing::TestApp::advance) двигает их: строка большого изображения становится готовой к захвату минутой позже, и вторая доставка делает миниатюру.
Эта минута не занимает времени.
Обращения к базе данных выполняются вне остановленных часов, поэтому часы не перескакивают вперёд, пока база данных отвечает.
Аренда истекает так же, когда часы проходят её срок.
Таблица на [часах базы данных](../components/time/database-clock.md) читает время базы данных, которое часы теста не двигают, а [собственные часы сервиса](../components/time/clock.md) продолжают действовать; тесты таких таблиц работают на реальных часах.

Сервис, который в промышленной среде работает на Postgres, тестируется тоже на Postgres: SQLite выполняет другой SQL, и в нём нет блокировок строк, уведомлений и выбора уровня изоляции.
[`TestApp::start_live`](../components/testing/live.md) подключает приложение обычным способом и ждёт на реальных часах.
Тест берёт на сервере собственную базу данных и создаёт таблицу в ней, поэтому ничего, что оставил предыдущий запуск, он не читает; `live::postgres::database` - вспомогательная функция тестов репозитория, а [`#[sqlx::test]`](https://docs.rs/sqlx/0.9/sqlx/attr.test.html) даёт тесту то же самое: базу данных с применёнными миграциями.
Тест читает адрес сервера из `POSTGRES_TEST_URL` и без него пропускается, поэтому `cargo test` проходит на машине без сервера; `RUSTSTREAM_REQUIRE_LIVE=1` превращает этот пропуск в ошибку там, где сервер обязан быть.
Сценарий тот же, что и в процессе, без изменений.

```bash
cargo test
POSTGRES_TEST_URL=postgres://user:password@localhost:5432/postgres cargo test
```

## Outbox в тестах {/* #the-outbox-in-tests */}

Тестовая сборка оставляет [outbox](outbox.md) выключенным, если его не включает `RUSTSTREAM_SQLX_OUTBOX=on`, поэтому собственные тесты сервиса запускают его обработчики без отслеживания.
Тест самого отслеживания работает с заданным переключателем и без него пропускается ([Переключатель](../components/outbox/switch.md)).
