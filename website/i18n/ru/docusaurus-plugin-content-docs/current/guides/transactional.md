# Ровно один раз внутри базы данных: транзакционные обработчики

Это руководство фиксирует записи обработчика вместе с завершением его задачи, поэтому задача, результат которой - строки в той же базе данных, вступает в силу ровно один раз.

Очередь доставляет каждую задачу хотя бы один раз.
Обработчик, который записал свой результат и аварийно завершился до завершения задачи, запускается снова и записывает результат дважды.
Когда результат - строки в той базе данных, где лежит очередь, этот дубликат убирает одна транзакция: записи и завершение фиксируются вместе или не фиксируется ничего.

Пример - сервис возвратов.
Возврат записывает свою строку в `refunds` и задачу на чек для сервиса рассылки, а затем вызывает процессинг карт.

[`.transactional()`](../components/transactions/index.md) в точке монтирования предоставляет обработчику транзакцию его доставки.
Обработчик принимает её первым параметром `Ctx`, `Ctx<keys::Tx<Sqlite>>`, и пишет через `&mut *tx`.
Обработчик, который принимает `keys::Tx` в подписке без этого шага, не компилируется.

Подтверждение фиксирует строку в `refunds`, задачу на чек и завершение строки возврата в одной транзакции.
Любой другой исход сначала откатывает записи, а затем завершает строку; переобработка всё равно засчитывает попытку.
Паника не фиксирует ничего.
Второй возврат того же заказа возвращает ошибку на первичном ключе `refunds` и отбрасывается, поэтому дубликат, попавший в очередь, ничего не меняет.

Задача на чек образует цепочку: сервис рассылки видит её, только когда возврат зафиксирован, и никогда - для возврата, который откатился.
Запись через [`Ctx<keys::Pool>`](../components/context/pool.md) фиксируется сама по себе, каким бы ни был исход, как и публикация через брокер; ни то ни другое в транзакцию не входит.

## Что остаётся снаружи {/* #what-stays-outside */}

Процессинг карт находится вне базы данных, поэтому его не покрывает никакая транзакция.
Переобработка после того, как процессинг уже вернул деньги на карту, вызывает его снова, поэтому вызов передаёт ключ идемпотентности, здесь заказ, и процессинг выполняет возврат один раз.
Так же хотя бы один раз остаётся каждый эффект вне базы данных: письмо, вызов HTTP, публикация в другой брокер.
С публикациями работают руководства [Ретрансляция событий в другой брокер](relay.md) и [outbox](outbox.md).

На SQLite транзакция доставки берёт блокировку записи базы данных при первой записи и держит её, пока доставка не завершится, и всё это время не пускает других писателей, включая захваты.
Здесь вызов процессинга выполняется после двух вставок, поэтому, пока он идёт, база данных заблокирована для других писателей.
Сервер блокирует только строки, которые записала транзакция.
Обработчик, который публикует сообщение, отслеживаемое [outbox](outbox.md), на SQLite публикует его до своей первой записи через `tx`: запись outbox пишется на собственном соединении, а ему нужна блокировка записи, которую держит доставка.
Отслеживаемая публикация после этой записи завершается ошибкой [`OutboxError::WriteLockHeld`](../components/outbox/outbox-error.md), и сообщение не отправляется.

## Изоляция {/* #isolation */}

Транзакция каждой доставки открывается на [уровне изоляции](../components/transactions/isolation.md) таблицы, `#[inbox(isolation = read_committed)]` на сервере, или в её режиме SQLite, `#[inbox(mode = immediate)]`.
Таблица, которая не объявляет ни того ни другого, получает уровень базы данных по умолчанию, а на MySQL и MariaDB - READ COMMITTED.
Каждая доставка в работе держит соединение для своей транзакции, поэтому обработчику, который берёт второе через `keys::Pool` или публикацию, нужен пул больше его `workers(n)`.
Транзакционный режим обслуживает одиночные доставки; обработчик пакетов, смонтированный с ним, не компилируется.
На MySQL и MariaDB обработчик, который прерывает оператор через `tx`, как это делает `select!` вокруг запроса, может нарушить следующее за ним завершение. Это ошибка sqlx-mysql 0.9.0: дайте каждому оператору завершиться.

## Тестирование {/* #testing */}

Тесты в файле примера запускают сервис через [`TestApp::start`](../components/testing/index.md) на SQLite в памяти и читают таблицы после каждой публикации.
Возврат фиксирует одну строку в `refunds` и один чек.
Возврат, первый вызов процессинга которого истёк по тайм-ауту, переобрабатывается, и вторая попытка оставляет одну строку в `refunds` и один чек, а не по два.
Тот же возврат, опубликованный дважды, во второй раз отбрасывается.
