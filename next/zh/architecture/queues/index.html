    • 队列
    英文版本为准

    本页译自英文，由模型翻译。若与英文原文存在差异，以英文原文为准。

    表

    队列就是服务自己的一张表：一行是一条消息，一个组是一个队列，各列的角色决定一行何时到期，以及结果做什么。

    本 crate 不创建表，也不执行迁移。CREATE TABLE 由服务编写，再由一个结构体向本 crate 描述这张表：#[derive(Inbox)] 从属性中读取描述，InboxTable 加 InboxSpec 是手写的同一种描述。每一行都由服务自己的 Publish 实现写入，因此插入语句的写法也由服务决定。

    一行在满足四个条件时可以领取，每个条件只在表有对应的列时才适用：该行属于订阅的组，它的 retry_after 已过，它的 processed_at 为空，并且没有租约占有它（locked_until 为空或已过）。领取按领取顺序取可领取的行：先看 priority，值越小越早，然后看 retry_after，最后看 id。retry_after 在将来的行是一个排期任务：在时间到来之前，队列看不到它。

    订阅的名称选定它的队列。在有 group 列的表中，名称就是组，每个组都是一个独立的队列。在没有这一列的表中，名称指向整张表。一个 Broker 为每个队列打开一个订阅：对同一张表和同一个组的第二个订阅，会让服务在启动时以 SqlxBrokerError::AlreadySubscribed 停止。多个 Broker 或服务的多个实例可以共享一个队列，领取方式让它们各自的行互不交叉。

    一行交给处理器什么，取决于两个角色。有 payload 列时，该行处于载荷模式：处理器接收由编解码器解码的载荷。没有这一列时，该行处于行模式：处理器接收驱动程序读出的行本身。headers 列把投递的消息头保存在一列中，在 json 特性下是一个由字符串组成的 JSON 对象。消息头布局则改为从各自的列中读取消息头，每个消息头一列。两者都没有的表投递空的消息头。

    “现在”在三个时刻读取：领取选择到期的行时、重试推迟一行时，以及 ack 标记一行时。默认由主机通过 SystemClock 读取，并以该列自己的类型绑定。设置 clock = DatabaseClock 后，语句改为读取数据库的时钟：

    数据库语句中的“现在”
    PostgreSQLstatement_timestamp()
    MySQL、MariaDBUTC_TIMESTAMP(6)
    SQLitestrftime('%Y-%m-%dT%H:%M:%f+00:00', 'now')，文本

    SQLite 以文本保存时间，并按文本比较，因此那里的表在每一行中都使用同一种时间格式。租约方式始终读取主机的时钟：使用 DatabaseClock 的租约表无法编译，原因见领取。

    领取如何把一行取来处理，见领取；每种结果写入什么，见结算。
